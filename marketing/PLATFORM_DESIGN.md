# 플랫폼별 사진 편집 디자인 · 2026-11-06

공개 소스를 읽고 참고한 원칙:
- https://github.com/codewithsadee/realvine : 사진을 크게 쓰고 메타정보를 사진 밖에서 구분하는 부동산 포트폴리오의 위계. 원본 HTML의 이미지·본문 구성 확인.
- https://github.com/timlrx/tailwind-nextjs-starter-blog/blob/main/layouts/PostLayout.tsx : 제한된 읽기 폭, 제목과 본문 간격, 기사형 콘텐츠의 흐름. 소스 확인.

참고는 구성 원칙에 한정한다. 외부 템플릿이나 사진을 앱에 넣지 않았다. 검수용 공개 예제 사진(property-1.jpg)은 청인마루 실적이 아니며 저장소에 포함하지 않는다. 네이버 원문과 외부 디자인 사이트는 네트워크 정책 때문에 직접 조사하지 못했다.

## 실제 출력
- 인스타 1080×1350: 여백의 미학(장별 사진·제목 순서 변주), 공간 갤러리(사진 전체와 절제된 그라데이션), 소재의 기록(비대칭 지면). 스토리·릴스 1080×1920.
- 네이버: 1080×720 기사 표지, 원본 비율 사진과 문단을 엮은 blog-preview.html. 글쓰기 API 연동 아님.
- 홈페이지: 승인본만 case.html/manifest.json으로 내보내며 큰 대표 사진과 상세 사진 전체, 반응형 제목과 제한된 본문 폭을 제공. 자동 공개 아님.
- 카카오: 1080×1080 사진 중심 사례 카드와 채널 원고. 메시지 자동 발송 아님.
- 채널 검토에 실제 출력 렌더러의 미리보기 제공. 입력 제목은 HTML 이스케이프, PNG는 생성 버전과 함께 기존 IndexedDB에 보관.

기존 제작 ZIP 가져오기, 사진 파일명 매칭, 수동 문구, 외부 보정 사진 유지, 브랜드 출력 형식은 보존한다. 피드/스토리 외 기존 출력 규격은 기존 브랜드 렌더러를 사용한다. 가격·고객 정보·비밀키를 추가하지 않았다. 사진 교정·승인본·백업 스키마는 변경하지 않았다.
