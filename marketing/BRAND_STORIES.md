# 청인마루 콘텐츠 방향 개편 · 2026-11-07

사진 등록 시 세 가지 콘텐츠 방향을 준비합니다. 살고 싶은 공간(공간에 마음이 가는 이유), 소재를 고르는 안목(확인된 모델·규격·색), 맡길 수 있는 시공(실제 선택한 작업과 살펴볼 기준)입니다. 캐러셀은 초대 → 공간 사진 → 제품 → 시공/선택 기준 → 상담의 흐름이며 3–6장에 맞춰 구성합니다. 모든 장을 표지처럼 만들지 않고 사진 중심 장과 제품 정보를 구분합니다.

- `content-engine.js`: 소비자의 선택에 닿는 제목·설명글·채널별 원고. 확인하지 않은 성능과 수행하지 않은 작업은 작성하지 않습니다. 브랜드명에 포함된 ‘마루’를 벽장재 문구로 잘못 치환하지 않습니다.
- `brand-story.js`: 사진 등록 후 콘텐츠 3안 자동 준비, 도감 선택과 규격 연동, 설명글 전환, 이전 문구로 되돌리기(최근 20회). 직접 수정한 문구와 가져온 제작 JSON은 임의로 교체하지 않습니다. 기존의 일반적인 ‘시공 기록’ 문구를 전환할 때는 기기 DB에 이전 상태를 보관합니다.
- `platform-design.js`: 사진 중심 표지, 사진에 여유를 주는 장, 실제 제품 정보, 시공/선택 기준, 상담 초대. 같은 소스 사진을 사용하며 자재 색·구조를 생성하거나 수정하지 않습니다.
- 승인된 채널 원고와 기존 생성 이미지, 원본 사진·저장소 버전은 유지합니다. 복원용 전체 백업에 새 작성 상태도 포함됩니다.

검증: Node 제품/문구/업무 규칙, `tests/brand_story_browser.py`의 3안·설명글·이전 원고 복원·직접 수정/재접속·반응형, `tests/workflow_browser.py`의 프로젝트/승인/일정/PNG/실제 H.264 MP4 전체 디코딩/백업 복원 통과. 루트 index.html, icon.jpg, maruni.png, ruru.png 해시 변경 없음.

복구는 백업 브랜치 `backup/before-brand-stories-20261106`에서 marketing/만 복원한 새 커밋을 main에 반영합니다. 기기의 IndexedDB나 실측 데이터를 삭제하지 않습니다. 실기기 OS의 사진 앱 저장은 이 검증 범위 밖이며 기존 Apple 공유 경로와 WebCodecs 기능 점검은 유지합니다.
