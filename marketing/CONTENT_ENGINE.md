# 청인마루 콘텐츠 자동 작성 엔진

`02 콘텐츠 구성`이 사진 → 제품 확인 → 작성 모드 → 제목 선택 → 수정·승인 → 게시 준비의 주 제작 화면입니다. 모델 API나 추가 비용 없이 브라우저에서 동작합니다. 슬로건은 **공간의 위로가 되다**입니다.

## 사실과 말투

전문적이고 절제된 문장으로 공간·제품·시공·신뢰·문의 중 필요한 요소만 조합합니다. 바닥재와 벽장재를 별도로 처리합니다. 제품군만 선택해도 작성할 수 있지만 브랜드·모델·규격·색상·소재를 만들어 넣지 않습니다. 사진에서 제품이나 시공 작업을 자동 판독하지 않습니다. 제품 자동 선택은 등록 제품이 하나이거나 현장에 이미 선택한 제품이 있는 경우에만 제한적으로 사용하며 사용자가 확인할 수 있습니다.

철거·샌딩·크랙 보수·덧방·황토풀 접착·코너 마감·문선 마감은 체크한 항목만 수행 문장에 포함됩니다. 현장 메모는 사용자가 확인한 사실로 취급하므로 사실만 입력하세요. 성능·인증·친환경성·방수·내구성·후기 등은 임의로 생성하지 않습니다. 직접 등록한 특징도 `특징 확인`과 `확인 출처`가 모두 있어야 문구에 사용합니다. 출처의 진위나 제조사 최신 사양을 자동 검증하는 서비스는 아닙니다.

## 제품 도감 / CSV

`03 제품 도감`에서 직접 등록·수정하거나 UTF-8 CSV를 미리보기 후 가져옵니다. 브랜드, 모델, 규격, 색상, 소재, 확인 특징·출처와 바닥재/벽장재 구분을 저장합니다. 기존 제품군 참고 도감은 유지합니다. 실측 프로그램의 제품 DB에는 접근하지 않습니다.

CSV 헤더:

```csv
type,category,brand,model,size,color,material,features,source,verified
floor,강마루,,,,,,,,false
wall,벽장재,,,,,,,,false
```

`type`은 `floor`/`wall` 또는 `바닥재`/`벽장재`입니다. 한글 헤더 `구분,제품군,브랜드,모델명,규격,색상,소재,확인된특징,확인출처,특징확인`도 지원합니다. 따옴표 안의 쉼표·줄바꿈, UTF-8 BOM을 처리합니다. `verified`는 `true`, `1`, `예`를 명시한 경우에만 참입니다. 파일 제한 2MB, 도감 1000개. 오류 행이 있으면 전체 가져오기를 중단합니다. 동일 제품 정보는 유지하고 다른 제품의 ID가 충돌하면 전체 적용을 중단합니다. 기존 제품을 CSV로 조용히 덮어쓰지 않습니다.

대표가 2026-11-05 첨부한 제품표의 91개 제품 계열과 377개 세부 모델·색상명을 가격 없이 기본 도감으로 추가했습니다. 출처·수치 검토·단종 표기를 보존하며 제조사 인증으로 간주하지 않습니다. 직접 등록과 CSV도 계속 사용할 수 있습니다. 테스트의 모델·규격·특징은 검증용 픽스처이며 실제 판매 제품 데이터가 아닙니다.

## 작성·승인·게시·성과

공간 화보형 / 제품 소개형 / 시공 전문형 / 소비자 궁금증형을 선택할 수 있습니다. 추천 근거는 입력한 작업·제품 정보·사용자가 지정한 사진 종류·실제 게시 이력입니다. 사진의 내용이나 제품 종류를 AI가 식별했다고 표시하지 않습니다.

한 번에 제목 3안, 인스타 게시글, 3–6장 캐러셀 구성·카드 문구, 릴스 후킹·대본, 스토리 문구, 해시태그, 고정댓글, 블로그 긴 글을 생성합니다. 기존 Shorts·카카오채널 초안도 제공합니다. 모든 문구는 수정하고 복사할 수 있습니다. 승인본과 이전 승인본을 현장과 함께 저장합니다. 입력 사실이 바뀌면 승인 상태를 해제하며 다시 작성하도록 안내합니다. 이전 버전의 `copyDrafts`는 읽기용 영역에 보존합니다.

최근 게시 완료 제목·본문 최대 30개와 한국어 문자 3-gram Jaccard 유사도를 비교하여 후보 중 덜 유사한 표현을 선택합니다. 브랜드명·선택한 제품명·슬로건은 비교에서 제외해 일관되게 유지합니다. 반복 가능한 사실이 많아 유사도가 높으면 검토 안내를 표시합니다. 무한한 독창성이나 의미 수준 중복 제거를 보장하는 생성형 모델은 아닙니다.

승인 → 게시 일정 저장은 승인 스냅샷과 제품 스냅샷·작성 모드·주제를 게시물에 연결합니다. `게시 완료`로 바꾼 때만 표현 이력에 등록하며 승인만으로 게시 완료 이력을 만들지 않습니다. 팔로워 증가·저장·공유는 기존 게시물별 인사이트, 상담은 기존 유입 게시물 ID로 연결합니다. 기록된 게시 완료 콘텐츠가 3건 이상이고 유형이 2종 이상인 경우에만 실제 평균 신규 팔로워와 상담 합계를 참고합니다. 표본 수와 관측값을 표시하며 성공 확률·예측 점수를 만들지 않습니다. Meta 자동 게시·수집은 여전히 미연결입니다.

## 데이터 보존

DB명·오브젝트스토어·기존 `version:1`, `officeVersion:2`를 유지하고 선택적 `contentEngineVersion:1`, `catalog`, `contentHistory`, `authoring`을 추가합니다. 첫 업그레이드에서 원본을 `pre-content-engine-v1` 키에 저장한 뒤 같은 트랜잭션으로 current를 확장합니다. 반복 마이그레이션의 이전 사본은 별도 시간 키에 보존합니다. 업데이트 전 JSON은 콘텐츠 화면의 이전 문구 영역에서 내려받을 수 있습니다.

전체 백업은 현재 현장, 보관함, 기존 v1 사본과 콘텐츠 업데이트 전 사본을 포함합니다. 기존 형식 백업도 복원합니다. 복원 전 사본·현장·확장 데이터를 모두 검사하며 프로젝트 전환 후에도 도감과 게시 이력은 유지합니다. 원본 실측 파일과 localStorage는 변경하지 않습니다.
