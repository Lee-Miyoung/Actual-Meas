# 청인마루 AI 마케팅 오피스

독립 앱 경로: `marketing/`. GitHub Pages: https://lee-miyoung.github.io/Actual-Meas/marketing/

루트 스마트 실측 시스템, `index.html`, `icon.jpg`, `maruni.png`, `ruru.png`는 수정하지 않습니다. 각 작업은 기존 체크아웃을 사용하며 명시적 요청 없이 worktree를 만들지 않습니다.

## 실행과 구조

저장소 루트에서 `python -m http.server 8000 --bind 127.0.0.1`. 빌드·패키지 설치 없이 동작합니다. 개발 검증은 로컬 HTTP로 실행하고 실제 개인정보가 없는 새 브라우저 프로필을 사용하세요.

- `studio.js`: 기존 사진 보정·출력과 v1 저장 기반.
- `office.js`: 호환성 마이그레이션, 사진 분석·보정 승인, 채널별 콘텐츠, MP4, 현장 보관함·성장·상담 운영.
- `studio.css`: 반응형 편집 환경.
- `fonts/`: SIL OFL 한글 명조/고딕 웹폰트와 라이선스. Fontsource Noto Serif KR 5.2.7, Noto Sans KR 5.2.9, 400 weight. 외부 폰트 서버에 의존하지 않습니다.
- `server/`: 별도 호스팅용 AI 편집 게이트웨이. Pages에서 실행되지 않습니다. [서버 설정](server/README.md).
- `tests/`: 합성 픽스처 기반 재현 가능한 브라우저 테스트와 게이트웨이 계약 테스트.

## 대표 작업 흐름

1. 현장명·지역·브랜드·제품과 확인된 메모를 입력하고 사진 4–10장을 올립니다.
2. 사진 1–10장을 올리면 기본 보정·문구·디자인 3안을 자동으로 준비합니다. 개별 사진 확정은 필수 조건이 아닙니다. 원본 비교와 세밀 보정은 필요할 때만 펼칩니다. 노출·WB는 보수적으로 추천하며 자동 원근 추정은 하지 않습니다. 수평은 선 방향 분석 참고값이고, 원근과 구도는 수동 조정할 수 있습니다. 원근·회전의 빈 가장자리는 크롭합니다.
3. 팔로워 확보/시공 신뢰/상담 유도 목적과 3–6장 분량을 선택해 매거진·갤러리·소재 기록 3안을 비교합니다. 추천 순서와 구도 중심을 반영하며 최종 크롭을 확인해야 합니다.
4. PNG 캐러셀·스토리·릴스 표지를 저장합니다. 채널별 문구를 검토·수정·복사하고 게시 일정을 등록합니다. 직접 수정한 문구는 자동저장되며 같은 현장 정보로 다시 생성해도 유지됩니다. 현장 사실이 바뀌면 새 정보에 맞는 기본 문구를 제안합니다. 무음 15초 릴스를 H.264 MP4로 출력할 수 있습니다. 지원 코덱이 없는 브라우저에는 미지원 안내가 표시되며 최신 Chrome/Safari를 사용하세요. 출력 중 탭을 열어 두어야 합니다. 음악은 플랫폼의 상업적 사용권을 확인해 추가하세요.
5. 게시물별 신규 팔로워·도달·조회·저장·공유·프로필 방문을 입력합니다. 같은 게시물은 갱신되며 중복 합산하지 않습니다. 월 콘텐츠 귀속 팔로워 증가와 목표를 비교합니다. 계정 순증가·현재 전체 팔로워와 혼동하지 마세요.
6. 상담은 별칭·유입 게시물·경로·상담→실측→견적→계약 단계와 내부 견적 참조번호만 기록합니다. 실측 앱에는 쓰지 않습니다. 개인정보를 최소화하고 공용 기기를 피하세요.

분석은 입력된 실제 기록에 기반한 규칙입니다. 실제 팔로워·상담 증가를 보장하거나 예측하지 않습니다. 다음 콘텐츠 참고 점수는 신규 팔로워 + 상담×3 + 계약×10이며 화면에 공개합니다. 소비자 질문을 소재함에 축적할 수 있습니다. 자동 팔로우·좋아요·댓글 기능은 없습니다.

## 데이터 보호와 호환성

기존 `cheonginmaru-marketing-v1` IndexedDB / `projects` 저장소 / `current` 키를 그대로 유지합니다. 기존 스키마 `version:1`과 모든 필드를 보존하고 `officeVersion:2`의 추가 필드를 사용합니다. 구 버전 자료를 처음 열 때 `pre-office-v2`에 원본 사본을 저장하고 새 current를 같은 트랜잭션으로 기록합니다. 실패 시 기존 자료를 덮어쓰지 않습니다. 구형 JSON 백업도 복원할 수 있습니다.

현장 스냅샷은 `project:<id>`에 보관합니다. 현장 전환은 현재 운영 기록을 유지합니다. 전체 JSON 백업은 current, 현장 보관함, 업그레이드 전 사본을 포함합니다. 복원은 형식·이미지를 검증하고 현재 전체 백업을 내려받은 뒤 확인받습니다. 복원 직전 current도 별도 키에 보존하며 보관함을 삭제하지 않습니다. DB 저장 실패 시 오류가 표시됩니다. 브라우저 데이터 삭제·기기 유실을 대비해 정기적으로 백업을 내려받으세요.

실측 localStorage에는 접근하지 않습니다. API 키·서버 접속 토큰을 IndexedDB나 JSON 백업에 저장하지 않습니다. 사진은 AI 기능을 명시적으로 사용하지 않는 한 기기 밖으로 보내지 않습니다.

## 플랫폼 출력과 ChatGPT 제작 설정

사진 & 디자인의 공통 디자인 패널에서 명조체, 중앙 흰색 로고(너비 18%, 불투명도 15% 기본), 제품명과 확인된 규격을 관리합니다. 기본은 상단 여백에 문구를 배치하고 전체 사진을 보존합니다. 인스타 피드 1080×1350, 카카오 캐러셀 800×800/기본 메시지 800×600, 유튜브 게시물 1080×1080, 영상 썸네일 1280×720, 스토리·릴스·쇼츠 1080×1920을 제공합니다. 네이버 본문은 원본 비율을 유지해 긴 변 최대 1600px, 대표사진은 1200×1200 앱 기본값입니다. 이는 제작 프리셋이며 플랫폼의 업로드 의무 규격과 구분합니다.

‘ChatGPT 작업 요청문 복사’ → ChatGPT에서 사진 보정·문구 작성 → 보정 사진 등록 → 제작 설정 JSON 붙여넣기 → 적용 순서로 사용합니다. 연결은 수동 전달이며 API 비용이나 인증 서버가 필요하지 않습니다. 자동 대화 동기화·자동 게시 기능은 추가하지 않았습니다. 요청문은 앱이 생성하며 사진·고객 자료를 외부로 자동 전송하지 않습니다.

`cheonginmaru-production-v1` JSON은 `product`, `size`, `format`, `slides`(3~6개, `title`/`photo` 파일명), `captions`(플랫폼 키별 설명글)를 받습니다. 붙여넣은 문구가 렌더링에 우선 적용되며 제품 정보는 사용자가 확인한 내용입니다. 플랫폼 전환 시 해당 설명글을 편집·복사할 수 있고 일괄 ZIP에 플랫폼별 PNG와 설명글이 저장됩니다. 보정 사진에는 문구·로고를 넣지 않아야 중복 합성이 생기지 않습니다.

기존 릴스 MP4 출력은 같은 공통 렌더러를 사용합니다. 음악 없는 15초 1080×1920 영상이며 MP4 MediaRecorder를 지원하는 브라우저가 필요합니다.

### 사진 중심 제작 화면 (2026-11-06)

사진 & 디자인에서 제작 ZIP 하나를 선택하면 `production.json`과 연결된 사진 3–6장을 검사한 뒤 함께 불러옵니다. ZIP을 풀어 사진과 JSON을 동시에 선택해도 됩니다. 파일명은 확장자만 바뀐 PNG/JPG도 연결하며, 누락·중복·손상 파일은 기존 작업을 교체하기 전에 거절합니다. 이전 작업을 교체할 때 확인창이 표시됩니다.

한 장씩 큰 미리보기와 사진 목록으로 확인하며 현재 문구·사진 연결·위아래 구도를 수정할 수 있습니다. 기본 출력은 사진 폭을 끝까지 채워 양옆 테두리를 없애고, 명조체 문구는 아래에 배치합니다. 제품·규격은 첫 장만 표시합니다. 플랫폼 비율 때문에 가장자리가 잘릴 수 있으며, 전체 사진 보존을 선택하면 고정 규격 대신 원본 비율로 출력합니다. 블로그 본문은 원본 비율 사진과 별도 캡션을 사용합니다.
