# 청인마루 마루니·루루 고정 4컷 템플릿 (2026-11-18)

## 운영 위치
마케팅앱 `marketing/index.html` → **01 사진 & 디자인** → **마루니·루루 4컷 고정 템플릿**.

기존 6컷 자유 편집기(마루니·루루 현장 이야기)는 삭제하거나 데이터 형식을 변경하지 않습니다.

## 반드시 고정할 항목
- **5개 결과물**: 썸네일 1장 + 만화 본편 4장, 각 **1080×1350px**, PNG 개별 저장 또는 5장 ZIP.
- **로고**: 썸네일 1회만 `brand/logo-black.svg`를 **공식 로고 패스 그대로** 넣습니다. 본편 4컷에는 넣지 않습니다. 임의 로고 생성, 재도형화, 비율 변경 금지.
- **캐릭터**: `assets/characters/manifest.json`의 `status:ready` **등록된 PNG 원본만 사용**. 표정·귀·얼굴·의상·명찰을 재생성하지 않습니다. 선택 가능 포즈는 등록된 것만. 루루 얼굴의 흰 무늬 추가 금지, 귀 모양 변경 금지.
- **장식**: 별도 반짝임, 느낌표, 광선, 이모티콘 효과를 새로 추가하지 않습니다. 이미 등록된 원본 PNG에 그려진 효과는 해당 포즈의 일부이므로 원본 파일을 수정하지 않습니다.
- **폰트와 말풍선**: `Maruni Story` 폰트 (자체 호스팅), 녹색/브론즈/잉크 팔레트, 둥근 흰색 말풍선 1개. 본편마다 제목·말풍선·하단 문구 크기, 줄간격, 위치 고정.
- **사진**: 사용자가 직접 첨부한 실사 파일만 합성. 바닥 색·결·벽 질감의 자동 변경 없음. 4:5 출력에 맞춘 중앙 크롭과 위아래 초점 조절만 지원. 사진을 다른 컷에 복사할 수 있습니다.
- **문구**: 사용자 입력 원문 그대로. 허용 길이 초과로 그려지지 않으면 짧게 수정하도록 안내. 글씨를 임의로 축소해 한 장마다 글자 크기가 달라지게 만들지 않습니다.

## 고정 배치 (좌표는 1080×1350 캔버스 기준)
- 표지: 공식 로고 (55,50,235×85); 시리즈 배지 (544,63,480×74); 질문형 제목 (88,289; 72px); 제품명 (80,543; 34px); 캐릭터 (하단 지정 위치); 하단 문구 (y=1204; 36px).
- 본편: 공통 시리즈명 (52,49; 30px); 제품명 (우측); 컷 번호 (54,142); 컷 제목 (185,152; 62px); 말풍선 (110,365,750×158; 43px, 1~2줄); 캐릭터 (하단); 하단 문구 (y=1203; 36px).
- 포즈만 바꾸며 캐릭터 이미지 자체는 원본 PNG 한 장입니다. 무작위 그림 생성 금지.

## 편집 가능한 값
현장 사진, 프로젝트명, 공통 시리즈명, 제품명, 확인된 규격, 시공 지역·분야, 질문형 제목, 4컷 제목, 컷당 말풍선 1개, 하단 문구, 공식 캐릭터 포즈와 좌/우 위치, 사진의 세로 초점.

## 저장 및 데이터 보호
- 별도 IndexedDB `cheonginmaru-maruni-locked-v1` 의 `projects` 객체 저장소에 작업을 저장합니다.
- 기존 실측 앱과 `cheonginmaru-marketing-v1`, `cheonginmaru-maruni-story-v1`에 쓰지 않습니다.
- 사진과 개인정보를 서버로 전송하지 않습니다. 등록된 캐릭터 Manifest/SVG/글꼴만 같은 호스트에서 가져옵니다.
- 사진은 장당 25MB 이하, 최대 4,800만 화소. 브라우저 데이터가 삭제되면 이 기기의 저장 작업도 지워질 수 있으므로 결과 ZIP을 별도 보관하세요.
- 아이폰 공유 메뉴는 가능할 때 호출하되 사진 앱 자동 저장을 약속하지 않습니다.
- 캡션 복사는 제목→제품/규격/지역→장면별 포인트→소개/문의→검색 태그의 순서를 사용합니다. 실제 확인되지 않은 제품 성능/규격은 자동 생성하지 않습니다.

## 검증 체크리스트
1. 썸네일과 본편 4장 모두 출력 크기 1080×1350, 5개 PNG ZIP.
2. 썸네일에만 공식 logo-black.svg 1회, 본편에는 로고 없음.
3. 캐릭터는 Manifest의 ready 자산에만 연결. 임의 재창작·루루 얼굴 변경 없음.
4. 고정 폰트/말풍선/여백; 긴 문구는 에러 표시하며 임의 축소되지 않음.
5. 사진 바꾸기 전 확인, 컷 간 복사, 개별 PNG, ZIP, 캡션 복사.
6. 새 작업/불러오기/자동 저장, 이전 6컷·기존 마케팅/견적 저장소 불변.
7. Safari/iPad에서 파일 선택, 터치, PNG 공유 시트 동작은 기기에서 최종 검수 필요.

## 아이패드 사용·성능 개선 (2026-11-19)
- **고정 5장 편집기**: 캐릭터 선택은 글자 목록만 보지 않고 마루니·루루 그림 버튼을 누른 뒤 6개씩 넘겨 봅니다. 이름·태그 검색, 선택한 컷에서 숨기기, 크기 슬라이더, 미리보기 캐릭터 손가락 드래그를 지원합니다. 고정 포맷과 공식 PNG 자체는 수정하지 않습니다.
- **미리보기 경량화**: 미리보기 내부는 540×675px, 최종 PNG는 기존 1080×1350px. 원본 사진은 파일 그대로 보존하고, 미리보기용 디코딩은 긴 변 2048px 이하·최근 2장만 메모리에 유지합니다. 장면 그리기는 애니메이션 프레임에 합쳐 중복 처리를 줄입니다.
- **사진 1회 저장**: 기존 프로젝트 저장소 이름은 유지하면서 IndexedDB 버전을 2로 올리고, 사진 Blob은 새 \`media\` 저장소, 글/포즈/장면 정보는 \`projects\`에 분리합니다. 과거 프로젝트가 보유한 사진은 불러오기와 다음 저장 과정에서 자동 호환됩니다. 같은 사진 여러 컷 복사 시 같은 사진 키를 씁니다. 사용자 작업 삭제나 데이터 초기화는 하지 않습니다.
- **기존 6컷 자유 편집기**: 30개 공식 포즈 이미지를 한꺼번에 그리지 않고 한 페이지에 6개만 표시합니다. 두 편집기 모두 사용자가 패널을 열 때만 시작하도록 바꿨습니다.
- **아이패드 터치**: 캔버스에서 캐릭터를 잡고 끌어 이동하며, 글씨·로고·말풍선은 이동하지 않습니다. 터치 영역 밖은 기존 페이지 스크롤을 이용합니다. 내보내기는 PNG/ZIP이고, iOS 공유 화면에서 사용자가 직접 사진 저장을 선택합니다.
- **검증**: 코드 파싱, 저장소 분리, 원본 로고 재사용, 캐릭터 목록 페이지 구분, 1080×1350 출력 계약을 검사했습니다. **실제 물리 iPad Safari의 터치·메모리·파일 공유는 추가 사용 검수가 필요**합니다.

## iPad 사진 선택 시 화면 가림 해결 (2026-11-19)
- 원인: 간편 마케팅 모드의 아이패드 CSS에서 body와 main을 100dvh 높이로 고정하고 overflow:hidden을 적용하여 독립 캐릭터 편집기를 아래로 스크롤할 수 없었습니다. sticky 미리보기까지 겹쳤습니다.
- 고정 5장 또는 자유 6컷 편집기를 열면 body에 maruni-editor-scrolling 클래스를 부여해 iPad의 페이지 세로 스크롤을 복구하고 미리보기 고정을 해제합니다. 두 편집기를 닫으면 기존 간편 화면 배치를 되돌립니다.
- 편집 중 다른 제작 패널을 접어 높이 충돌을 방지하며, 실제 데이터·사진을 변경하거나 삭제하지 않습니다.
- 고정 5장과 자유 6컷 모두 미리보기 위에 현재 컷 사진 선택 버튼을 추가했습니다. iOS 자체의 사진 선택 시트는 수정할 수 없습니다.
- 확인 사항: iPad 가로와 세로에서 사진 선택 후 캐릭터 설정, 말풍선, PNG·ZIP 저장까지 아래로 스크롤 가능한지 검사. 이후 편집기를 닫으면 간편 화면으로 돌아오는지 검사.
- 기존 인스타 1080×1350, 로고는 썸네일에만, 공식 캐릭터 파일, 고정 말풍선 형식은 유지합니다.

## 제품·시공·일상 이야기 템플릿과 사진 일괄 입력 (2026-11-19)
- 콘텐츠 형식 선택: 제품 소개, 시공 에피소드, 시공 과정·전후, 생활·관리 정보, 그냥 사는 이야기, 현장 밖 비하인드 총 6가지. 형식을 바꾸면 5장 제목/말풍선/하단 문구 예시만 변경하며 사진·캐릭터·위치와 컷 참조는 그대로 둡니다.
- 사진은 iPad 사진앱/파일앱에서 **다중선택**하여 넣거나, PC에서 끌어다 놓고, 복사한 이미지를 붙여넣을 수 있습니다. 브라우저 지원 범위에서 '복사한 사진 붙여넣기' 버튼도 제공합니다.
- 선택한 사진은 현재 컷부터 뒤쪽 컷 순서로 배치합니다. 넘친 이미지는 사진 보관함에 남습니다. 기존 이미지가 있으면 확인합니다.
- 사진 보관함은 20장까지, 한 화면에 6장씩 탐색하며, 썸네일을 탭하면 현재 컷에 적용됩니다. PC에서는 이미지가 들어 있는 썸네일을 다른 컷 번호나 캔버스로 드래그할 수 있습니다.
- 버튼 '사진 이전/다음 컷과 교환'은 **사진만** 바꾸며 해당 컷의 제목·말풍선·캐릭터는 그대로 유지합니다. '본편 순서 앞으로/뒤로'는 **해당 본편 장면 전체**를 옮깁니다. 표지는 순서 이동 대상에서 제외합니다.
- 캐릭터 카드를 누르면 해당 공식 PNG가 **즉시** 사진 위에 나타나고 선택됩니다. 포즈를 바꾸려면 '마루니/루루 다른 동작 보기' 버튼을 누른 뒤 그림을 선택합니다. 사진 위 캐릭터는 드래그로 위치를 조절합니다.
- 보관함에서 잘못 넣은 사진을 제외할 수 있습니다. 현재 컷에서 사용 중이면 확인 후 관련 컷의 사진을 비웁니다.
- 일반 일상 이야기·비하인드 형식의 캡션은 생활형 문장으로 바뀌며, 시공 상담 홍보 문구는 자동으로 넣지 않습니다. 제품·시공 형식은 기존 청인마루 문의 안내와 제품/지역 중심 해시태그를 유지합니다.
- 원본 로고는 표지 한 번만, 원본 캐릭터 PNG는 바이트 그대로, 썸네일과 본편은 1080×1350px, 고정 글씨·말풍선 스타일은 유지합니다.
- 사진 Blob은 기존 독립 IndexedDB `media` 저장소에 한 번만 등록하며, 프로젝트 `library`에는 사진 ID·이름만 보관합니다. 기존 작업의 사진도 복구하도록 중복 선언된 `openProject` 함수를 제거했습니다.
- 모든 사진은 기기 안에서 처리하며 외부 AI 전송이나 자동 게시 기능은 추가하지 않습니다.

## iPad 화면이 멈추는 것처럼 보일 때 · 기본 스크롤 모드 (2026-11-19)

- 기존 6컷 현장 이야기와 새 5장 고정 템플릿은 **둘 다 미리보기 위쪽에 ‘화면 스크롤 · 이동 끔’ 버튼**이 있습니다. 아이패드에서는 이 상태가 기본이며 사진 위에서 손가락으로 위아래 스크롤할 수 있습니다.
- 캐릭터를 옮길 때만 버튼을 눌러 **‘캐릭터 이동 켜짐’**으로 바꿉니다. 옮긴 후 다시 꺼야 화면을 스크롤하기 편합니다. 컴퓨터 마우스 이동은 평소대로 사용할 수 있습니다.
- 기존 6컷 편집기는 새 포즈를 선택할 때 **같은 종류의 기존 캐릭터 포즈를 교체**하며, 의도적으로 두 마루니 등을 놓으려면 **‘같은 캐릭터 추가’**를 켭니다. 사진이 없으면 먼저 사진을 넣도록 안내합니다.
- 예전에 잘못 여러 번 누른 캐릭터는 **‘겹친 캐릭터 정리’**를 눌러 확인 후 각 한 명만 남길 수 있습니다. 사용자 확인 없이 기존 장면을 자동 삭제하지 않으며 기존 6컷의 되돌리기 기능을 유지합니다.
- 기존 6컷에 **‘4컷 고정 템플릿 열기’** 버튼을 추가했습니다. 저장 후 별도 고정 편집기를 열지만 데이터 저장소가 다르므로 6컷 자료를 자동으로 옮기지는 않습니다.
- 6컷 미리보기에서 현재 장면의 캐릭터가 여러 개일 때 이미지 캐시가 계속 비워져 생기던 재디코딩 부담을 완화했습니다. 캐릭터 미리보기는 900px 이내로 디코딩하되 최종 PNG 내보내기는 원본 이미지를 별도로 읽어 **1080×1350**으로 출력합니다.
- 물리 아이패드 Safari의 터치 동작과 기기별 체감 속도는 별도 현장 확인이 필요합니다.
