# 청인마루 시그니처 디자인 시스템 — 2026-11-09

## 분석 및 변경 범위

기존 디자인은 `theme`와 현재 작업 설정에 의존했고, 새 현장마다 세 시안을 제안했습니다. 제품은 프로젝트 단일 선택값 중심이었으며, 기본 브랜드 설정·프로젝트별 디자인 버전·사진별 자재 스냅샷이 분리되지 않았습니다. 이를 `marketing/` 안에서 확장했습니다. 루트 실측·견적 계산식, 홈페이지·회계·고객관리 파일은 수정하지 않습니다.

## 구현

- **기본 디자인 설정**: 새 ‘브랜드 디자인 설정’ 화면에서 Editorial Studio, Modern Gallery, Material Journal을 동일 사진·정보로 비교합니다. 작업 화면의 반복적인 3안 선택은 제거했습니다.
- **고정 규칙**: `signature-core.js`의 ID·schema·version·revision, 팔레트, 서체, 제목/본문 크기·최소 크기·행간, 사진 fit/배치, 여백, 로고/현장/제품/규격/취급 브랜드 표시, 10개 플랫폼 규칙을 저장합니다. 기본값은 Editorial Studio와 요청한 네 색상입니다.
- **서체**: 기존 자체 호스팅 Noto Serif KR / Noto Sans KR를 사용합니다. `fonts/LICENSE-serif.txt`, `fonts/LICENSE-sans.txt`의 SIL Open Font License 1.1을 확인했습니다. 새 외부 폰트나 비용은 없습니다.
- **스냅샷**: 기본 설정은 기존 `settings.brandDesign`에, 각 현장의 전체 설정은 `signatureDesign`에 저장합니다. 기본값을 변경해도 이전 현장의 디자인은 자동 변경하지 않습니다. 기존 프로젝트는 `legacy-v6`로 유지하고 명시적으로 적용한 경우만 업그레이드합니다.
- **설정 관리**: 기본 설정 저장, 현재 현장에 명시적 적용, JSON 내보내기/가져오기(저장 전 초안), 이전 기본 설정 복원, 현재 현장 이전 디자인/당시 문구 복원을 지원합니다. 글로벌 설정 이력 12개와 프로젝트 메타데이터 이력 6개를 보존합니다. 이력에 사진 Base64를 중복 저장하지 않습니다.
- **캐러셀 구성**: 표지 → 실제 전후 자료가 있을 때 비교 → 공간 → 확인된 디테일 → 다른 시점 → 정보 카드로 구성합니다. 완공 여부는 사용자가 등록한 단계로 판단합니다. 전후 자료가 없으면 일반 사진으로 구성하며 비교를 지어내지 않습니다. 사진 5장 이상이면 기본 6장, 부족하면 실제 제공 사진+정보로 줄입니다. 정보 카드당 최대 2종의 자재를 표시하며 더 많은 자재가 있으면 정보 페이지를 추가합니다.
- **대표 사진**: 시공 후로 분류된 사진을 우선하고, 기존 로컬 사진 분석의 품질·중복 정보를 참고합니다. 사용자가 사진 연결과 초점 위치를 수정할 수 있습니다. 사진 수 부족을 감추기 위해 자동 반복하지 않습니다. 실제 전후 비교에 같은 ‘후’ 사진을 표지와 비교에 함께 사용하는 경우는 역할상 중복일 수 있습니다.
- **사진별 자재**: 사진별 역할·구역·제품 도감 모델/세부모델·확인한 특징을 저장합니다. 마루와 벽장재를 한 현장에 함께 연결합니다. 선택 당시 제품 스냅샷을 보존하여 이후 도감 편집이 과거 현장의 모델·규격을 바꾸지 않게 했습니다. 잘못된 제품 키는 다른 제품의 규격으로 대체하지 않습니다.
- **자동 정보 연결**: 기존 마케팅 보관함의 현장을 선택하면 공개 현장 정보와 등록 제품을 읽어 연결하며 현재 업로드 사진은 유지합니다. 원가·고객 연락처·비공개 고객 필드는 복사하지 않습니다.
- **공통 정보 원본**: 게시글·블로그·카카오·스토리·릴스 설명과 채널 초안은 같은 현장/사진별 제품 컨텍스트를 사용합니다. 확인한 작업과 입력한 사진 특징만 사용하고 성능·인증·후기는 생성하지 않습니다. 사용자가 직접 수정한 캡션과 승인된 원고는 보존합니다.
- **플랫폼 변환**: carousel, reels, story, naver, naverCover, kakao, kakaoWide, shorts, youtube, youtubeCover를 독립된 그리드로 렌더링합니다. carousel 1080×1350, 세로 1080×1920, 가로 썸네일 1280×720 등 기존 플랫폼 규격을 유지합니다. 네이버 본문은 사진 비율을 보존한 사진 영역+정보 여백의 자연 높이입니다. 정지 PNG 표지와 실제 H.264 MP4 내보내기는 구분합니다.
- **보관 채널**: 검토·승인·내보내기 버전에 디자인·구성·제품·사진 참조를 함께 고정합니다. 이후 기본 설정이나 현재 작업을 바꿔도 승인된 결과는 그 스냅샷으로 출력합니다.

## 사진·성능·데이터 보호

사진 색상·무늬·시공 방향을 변경하는 생성 처리를 추가하지 않았습니다. 기존 보정값은 그대로 사용합니다. 기본 fit은 전체 보존이며, 작은 원본을 억지로 확대하지 않습니다. 사용자가 채우기를 선택한 경우만 기존 초점/구도 규칙을 사용합니다. 전후 사진은 겹치지 않고 별도 영역에 표시합니다.

기존 미리보기 긴 변 960px, 확대 1440px, 작업 이미지 캐시 2장, 최신 요청 병합 및 순차 생성을 유지합니다. 설정 미리보기도 순차 실행하며 화면을 나갈 때 Canvas를 해제합니다. 사진별 제품 목록은 접힌 상태에서 만들지 않고 공용 자동완성 목록 하나를 사용합니다. 기존 전체 복원에서 원본 전체를 병렬 디코딩하던 부분을 순차 처리·즉시 해제로 바꿨습니다.

데이터베이스 이름과 스키마 버전은 유지합니다. 초기 도입 전 현재 작업을 `pre-signature-v1:<timestamp>` 키로 보존합니다. 기존 전체 백업/복원과 프로젝트 보관함은 그대로 사용합니다. 저장 검증의 3–6장 제한은 시그니처 스냅샷이 있는 프로젝트에만 1–16장으로 확장합니다. 일반 기존 제작 JSON의 3–6장 규칙은 유지하며, 시그니처 패키지 확장이 있는 경우에만 부족 사진/추가 정보 페이지를 허용합니다. 기존 출력 폴더 구조와 이미지 파일 형식은 변경하지 않습니다. 일괄 출력은 시작 시 디자인·사진·보정값·문구를 고정하고 Canvas를 즉시 해제합니다. ZIP에 추가한 출력안내는 릴스/쇼츠 폴더의 PNG 표지와 별도 MP4를 명확히 구분합니다.

## 검증 한계와 추가 연결 사항

1. 실제 iPad/iPhone·Windows·Android 하드웨어와 실제 iPad 장시간 사용/OS 종료 로그는 미검증입니다. 자동화된 WebKit을 실제 iPad 검증으로 주장하지 않습니다. OS 강제 종료를 방지한다고 보장하지 않습니다.
2. 이 요청에는 청인마루 고해상도 원본 현장 사진이 첨부되지 않았습니다. 합성 검증 이미지(밝은/어두운 장면, 좁은 세로/가로 혼합, 구도가 다른 전후 역할)와 공개 참고 사진으로 검증했습니다. 참고 사진과 도감 모델을 조합한 시연은 실제 시공 실적이나 제품 적용 증거가 아닙니다. 시연 사진·생성물은 배포 코드에 포함하지 않습니다.
3. 사진 역할 자동 제안은 **파일명 규칙**입니다. 시각적 장면을 AI로 확정하거나 사진에서 제품 브랜드·모델·규격을 알아냈다고 표시하지 않습니다. 확인 전 역할과 누락 제품은 그대로 미확인으로 처리합니다.
4. 루트 실측 v20.2의 `cm_v20_records` 저장 항목은 id·고객명·날짜·금액뿐이며 모델·규격·시공 구역이 없습니다. 이를 제품 데이터로 추측하지 않았습니다. 이번 연결은 **마케팅 현장 보관함**의 등록 정보입니다. 실측 프로그램과 완전 자동 연동하려면 향후 프로젝트 ID·공개 현장 정보·제품 ID/규격을 제공하는 읽기 전용 자료가 필요합니다. 실측 계산식·저장 형식은 수정하지 않았습니다.
5. 외부 AI·SNS 인증/자동 게시를 새로 연결하지 않았습니다. 이 시스템의 디자인·템플릿·파일 생성에는 별도 API 키나 사용 비용이 없습니다.

## 배포·복구

기존 main → GitHub Pages 방식과 `/marketing/` 경로를 유지합니다. 배포 전 변경 파일과 테스트 결과를 보고합니다. 이전 코드는 `backup/before-signature-system-20261109`에 보존합니다.

문제 발생 시 해당 브랜치의 `marketing/`만 새 커밋으로 복원해 정상 배포합니다. 루트 실측 파일이나 브라우저 저장소를 초기화하지 않습니다. 앱 설정 복원 버튼은 기본 브랜드 설정과 현장별 이전 디자인을 구분합니다. 모든 프로젝트는 기존 전체 백업 JSON으로도 복원할 수 있습니다.

향후 렌더러 변경은 별도 버전으로 추가하고 `signatureDesign.version`에 맞는 렌더러를 유지해야 합니다. 이미 저장된 v1 레이아웃을 무단 수정하는 방식으로 새 버전을 배포하지 마세요.
