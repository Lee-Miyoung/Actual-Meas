## 변경 전후

기존에는 여러 사진 등록 위치, 독립 보정 사진 묶음, 디자인 선택과 채널 설정이 흩어져 있었다. 일상 메뉴를 **현장 보관함 / 콘텐츠 제작 / 게시 관리 / 성과 확인**으로 통합했다. 제품 도감·CSV, 기존 3개 테마, 상세 보정, 상담·계약, 전체 백업은 고급 관리에서 유지한다.

PC는 왼쪽 작업 도구와 오른쪽 큰 미리보기, 태블릿·모바일은 미리보기를 먼저 배치한다. 제품 선택은 접을 수 있고, 사진 추가 버튼과 전체 JSON 백업을 분명하게 표시한다. 처음 여는 사용자는 현장 보관함의 ‘새 현장 등록’으로 시작한다. 기존 마지막 작업 메뉴는 재접속 때 유지한다.

기존 `state.photos`가 공용 원본 사진함이다. 새로운 DB나 복제 사진함으로 옮기지 않았다. 기본 업로드는 최대 30장, 장당 20MB·현장 합계 80MB까지 순차 처리한다. SHA-256으로 정확한 중복을 건너뛴다. 제외는 삭제가 아니며, 사진 교체와 복원 양쪽 원본 버전도 기존 자산 저장소에 보관한다.

## 사진 정리와 디자인

- 원본 파일·해상도는 유지하고 승인한 회전·원근·크롭 파라미터만 별도로 보관한다.
- 기본 전체 색상 필터, 화이트밸런스, 색온도·채도 조정은 적용하지 않는다. 바닥 영역을 확신할 수 없으면 사진 전체 색상을 보호한다.
- 기존 로컬 구조선 분석으로 보수적인 수평·수직 원근 추천을 만든다. 회전 ±1.5°, 원근 ±0.035, 잘림 6% 한도이며 불확실하면 원본을 유지한다. 적용 전 원본/추천 비교와 승인이 필요하다.
- 기본 도구는 자동 구도 정리 / 수평·원근 조정 / 주변 정리 / 원본 비교다. 이전 상세 보정 도구와 수동 비바닥 마스크 보정은 고급 관리에 남아 있다.
- 사진 종류는 파일명으로만 추천하고 사용자가 일괄 또는 개별 확인한다. 이미지 내용 AI 분류라고 표시하지 않는다. 보호재 표시·미확인 사진은 자동 대표 완공 사진에서 제외한다.
- A 대표 표지 / B 완성 공간 / C 디테일 / D 과정 / E 전후 비교를 한 스타일로 구성한다. Noto Serif KR 제목과 Pretendard 정보 글꼴은 기존 로컬 자산을 사용한다.
- 대표 표지에 기존 공식 로고를 작은 크기로 표시하고 나머지는 기본 OFF다. 관리자에서 크기·불투명도·위치와 다른 카드 표시 여부를 변경할 수 있다. 로고 원본은 수정하지 않았다.
- 최대 6장의 실제 사진만 추천한다. 없는 공정·공간은 만들지 않고, 수동 순서·문구는 재추천해도 보존한다. 분류나 보호재 상태가 바뀌면 완성컷 자격을 다시 확인한다.
- E는 같은 공간이고 직접 비교 가능한 촬영 시점임을 사용자가 확인한 실제 두 사진만 연결한다. 자동으로 전후 이미지를 합성하거나 바닥을 생성하지 않는다.
- 제품은 실제 선택한 브랜드·제품·모델·규격 스냅샷만 사용한다. 가격·단가·고객 상담 정보는 출력물에 포함하지 않는다.

승인한 기본 디자인은 버전으로 보관해 새 현장에 적용한다. 이전 프로젝트와 게시물의 고정 디자인은 자동 변경하지 않는다. 기존 프로젝트는 명시적으로 통합 디자인을 적용해야 바뀐다.

## 아직 필요한 검수·설정

1. **단독주택 / 노바 플로 애프터눈 오크 원본 사진**이 없다. 실제 사진을 받으면 A–E 5종과 원본/보정 비교를 재출력해 색감·결·수평·잘림·문구·로고를 확인해야 한다. 현재 샘플은 합성 기능 검수용이며 실제 시공 사례로 사용하면 안 된다.
2. 실제 아이폰·아이패드 Safari에서 파일 선택, 장시간 영상 출력, 공유→사진 저장을 확인해야 한다. WebKitGTK는 실제 iOS와 같은 기기가 아니다. H.264 WebCodecs를 제공하지 않는 브라우저는 PNG를 사용할 수 있고 MP4는 지원 안내를 표시한다.
3. 렌즈 모델별 배럴/광각 프로필 교정, 의미 기반 바닥 감지·여백 인식, 사진 내용 AI 분류, 자동 잡동사니 감지는 구현하지 않았다. 현재 구조선 분석과 사용자 분류·확인을 사용한다.
4. 어두운 비바닥 영역은 기존 수동 경계 마스크를 확인한 경우에만 보정할 수 있다. 의미 기반 자동 노출은 연결하지 않았으며 전체 자동 노출은 기본 OFF다.
5. AI 주변 제거는 기존 게이트웨이의 실제 연결·인증·서버 AI 키·사용량/비용 설정이 필요하다. 현재 기본 비활성이다. 연결 후에도 외부 전송 동의, 비바닥 영역 확인, 작은 마스크와 결과 승인을 요구한다. 보호재 아래 바닥 생성은 허용하지 않는다. 이 작업에서 유료 API를 호출하지 않았다.
6. 가로로 긴 사진을 자르지 않으면 세로 피드 표지의 사진 면적이 75% 미만일 수 있다. 비율 보존을 우선했으며, 실제 제공 사진으로 여백·보조 사진 구성을 검수해야 한다.
7. 이전 지시의 인증된 읽기 전용 제공 구조 확인 전 견적 연동 보류를 유지했다. 앱은 동일 출처의 가격 없는 마지막 제품 목록과 수동/CSV 도감을 사용하며, 브라우저에서 견적 원본 시트를 받지 않는다. 실시간 견적 서버 연결은 이번에 켜지 않았다.
8. 클라우드 동기화는 범위에서 제외했다. 다른 기기/브라우저에서는 전체 JSON 백업·복원으로 옮긴다. 영구 서버/CMS/SNS 자동 게시 연결도 별도 인증과 승인 사항이다.

## 복구 방법

현재는 배포 전이므로 운영 앱은 복구할 변경이 없다. 원격 백업 브랜치는 변경 전 main과 동일한 코드다.

승인·배포 후 문제가 생기면 **먼저 최신 전체 JSON 백업을 내려받고**, 리뉴얼 병합 커밋을 revert하는 별도 복구 브랜치를 만들어 검수 후 배포한다. 작업 트리 전체를 reset하거나 브라우저 데이터를 초기화하지 않는다. 코드 백업 브랜치는 고객 데이터 백업을 대신하지 않는다.

구버전은 10장 제한이 있어 새 30장 프로젝트 백업을 바로 읽지 못할 수 있다. 기존 버전으로 내려가기 전에 JSON과 원본 ZIP을 보관하고, 필요하면 이 개발 버전에서 데이터를 열어 내보낸다. 브라우저 DB 삭제로 해결하지 않는다. 원래 10장 이하 구버전 백업의 새 버전 복원은 호환되며, 복원 전 기존 앱의 자동 전체 백업 절차를 유지한다.
