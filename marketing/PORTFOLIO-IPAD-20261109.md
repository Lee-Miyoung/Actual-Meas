`marketing/` 내부만 변경했습니다. 기존 원본 로고, 사진 순서, 원본 사진 데이터, 보정값, 프로젝트·채널 원고, 제품 도감과 데이터베이스 스키마를 유지합니다. 추가 저장 필드는 프로젝트의 `productionView.slide`뿐입니다. 고객 정보나 사진은 GitHub에 추가하지 않았습니다.

## 확인한 문제와 근거

- 기존 `renderProductionWorkspace`는 요청마다 Canvas를 만들었습니다. revision 검사는 모든 처리가 끝난 뒤 실행되어 오래된 결과의 화면 반영만 막고, 동시 생성은 막지 못했습니다.
- WebKit에서 단순 직렬화만 적용하면 80회 연속 요청이 81회 생성으로 이어졌습니다. 24ms 동안 요청을 모은 뒤 최신 화면만 처리하도록 수정한 후 같은 테스트는 생성 1회, 최대 동시 생성 1회였습니다. Chromium에서도 동일 결과를 확인했습니다.
- 편집 미리보기의 변환 Canvas와 단일 이미지 내보내기 Canvas를 사용 직후 해제하지 않았습니다. 이제 임시 Canvas를 해제하며, 오래된 편집 요청은 변환 전에 취소합니다.
- 동일 원본의 `photoImage()` 호출에 진행 중인 디코딩을 공유하는 장치가 없었습니다. 이제 동일 사진의 요청은 공유하고, 작업 사진 디코딩은 순차 실행합니다. 작업 캐시는 두 장으로 제한합니다.
- 원본 검증·작업 이미지 생성·160px 분석이 원본을 재차 디코딩했습니다. 업로드 검증 때 작업 이미지와 썸네일을 한 번 만들고 분석까지 수행합니다. 이전 프로젝트에서 썸네일이 없으면 보이는 항목만 순차로 준비합니다.
- 저장 전에 `structuredClone(state)`를 만든 뒤 IndexedDB가 다시 복제했습니다. 이제 중복 사본을 없애고, 쓰는 동안 변경된 상태는 최신 내용으로 모아서 저장합니다. 숨김/페이지 이탈 시 미처리 저장을 시도합니다.
- iOS 저장창의 Blob URL과 이미지 DOM이 닫은 뒤에도 남았습니다. 닫을 때 모두 해제합니다.

이는 확인된 코드·자원 문제와 재현 가능한 성능 근거입니다. 실제 iPad Safari 종료 로그는 확보하지 못했으므로 OS가 탭을 종료한 원인으로 확정하지 않습니다. 강제 종료를 방지한다고 보장하지 않습니다.

## 화면 개선

- 시공 전후 합성본의 각 절반을 다시 크롭하지 않고 원본 비율로 배치합니다. 흰 네모 라벨 대신 사진 바깥의 작은 텍스트를 사용합니다.
- 비교 포트폴리오의 상단은 원본 로고와 실제 현장 정보만 표시합니다. 불필요한 우측 안내 문구를 제거했습니다.
- PC·iPad는 두 열, 휴대폰은 세로 한 열로 보여 줍니다. 고정 출력물의 여백 때문에 사진이 작아 보이지 않도록 화면용 비교 레이아웃을 별도로 구성했습니다. 사진 색상이나 질감을 추가 변경하지 않습니다.
- 제목·설명·제품 정보를 사진 바로 아래에 배치합니다. 기존 데이터만 사용합니다. 썸네일은 통일된 크기와 하단 선택선, 페이지 번호는 `04 / 06`, 이전/다음 터치 영역은 48px입니다.
- 사진 클릭·키보드로 확대, 화면 맞춤/확대, 터치 가로 이동을 제공합니다. 세로 스크롤과 핀치 제스처를 막지 않습니다.
- 화면용 Canvas 긴 변은 최대 960px, 확대용은 최대 1440px이며 PNG·MP4 저장 해상도는 기존 플랫폼 규격을 유지합니다.
- 마지막 프로젝트는 기존 IndexedDB 로딩 경로를, 선택 메뉴는 기존 로컬 저장 경로를 유지합니다. 마지막 사진 번호도 프로젝트별로 복원합니다. 저장 실패 시 오류를 표시하고 기존 자료를 유지하며 재시도할 수 있습니다.
