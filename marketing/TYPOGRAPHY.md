# 글자 배치·크기·조판 개편 · 2026-11-08

## 실제 확인한 참고 원문

- [Raster / Rasmus Andersson](https://github.com/rsms/raster/blob/master/raster2.css): `--lineHeight`, `--baseline`, 제목 크기 단계, 행간에 연결된 여백. 일관된 위계와 정렬 원칙을 참고했다. Raster CSS나 외부 폰트를 앱에 추가하지 않았다.
- [Tachyons type scale](https://github.com/tachyons-css/tachyons/blob/master/src/_type-scale.css): 제목·본문·보조 정보의 크기 단계와 모바일에서 너무 큰 제목·작은 글씨를 주의하라는 원문. 카드 역할마다 제목/정보 크기를 구분하고 메타정보 대비를 높였다.
- [W3C 한국어 조판 요구사항](https://github.com/w3c/klreq/blob/gh-pages/index.html), `h_line_breaking`/`line-break`: 한글의 어절 단위와 글자 단위 줄 나눔, 행두·행말 규칙. 제품명·단위 보존, 어절 우선 줄바꿈을 구현할 때 참고했다. 공식 인증이나 규격 준수 판정을 받은 것은 아니다.

## 적용

`typography.js`는 실제 폰트로 측정한 폭을 받아 조판한다. 어절 우선, 필요한 경우에만 글자 단위 분리, 괄호와 닫는 문장부호의 위치, 지나치게 짧은 마지막 줄을 고려한다. 제목의 쉼표 양쪽 구절이 읽을 수 있는 크기로 들어가면 의미 단위로 나눈다. 사용자 입력 줄바꿈은 유지한다. 모델명의 숫자와 두께 단위는 임의로 떨어뜨리지 않는다.

PNG 제목은 대략 62–76px 범위의 명조를 중심으로, 제품명과 본문은 별도 단계로 처리한다(1080px 기준). 제품 카드의 모델명은 42–36px, 규격·색상 값은 32–28px로 높이고 실제 줄 수에 따라 다음 정보의 위치를 계산한다. 제목 행간은 1.26, 정보 행간은 1.45를 사용한다. 실제 문구 길이에 따라 지정된 최소 크기까지 조절하고, 그 이상 넘치면 말줄임을 표시한다. 저장된 원문·승인본은 바꾸지 않는다. 필요한 한글 글리프를 로드한 뒤 그린다.

공간 시안은 사진 아래 여백에 제목, 소재 시안은 제목을 먼저 두고 사진·규격을 연결, 시공 시안은 짙은 배경에 밝은 제목을 배치한다. 상담 카드의 문장 덩어리와 제목/보조 문구/로고 간격을 정리했다. 스토리의 제품 정보는 하단 UI와 겹치지 않게 올렸다. 사진의 자재 색·구조는 수정하지 않았다.

모바일 상태 알림은 터치 입력을 가로막지 않는다. UI에도 제목/설명/보조 정보의 위계와 어절 단위 줄바꿈을 적용했다. 출력 이미지별 글자 경계 정보는 로컬 캔버스에만 붙여 검사하며 PNG나 외부 서버로 전송하지 않는다.

## 검증

- Node 27개 항목: 기존 제품 사실·ZIP·업무 규칙과 새 조판 5항목 PASS.
- 실제 한글 폰트로 3방향 × 6규격 × 5장 = 90개 조합: 글자/로고 충돌·캔버스 밖 잘림 없음. 긴 문구의 말줄임과 원문 보존 PASS.
- WebKitGTK 2.52.6: 한글 PNG, 기기별 화면, 저장 창, 원본·문구 복원, 1080×1920 H.264 MP4 전체 디코딩 PASS. 물리 iOS 기기나 OS 사진 앱을 직접 검증한 것은 아니다.
- 프로젝트·채널 승인·일정·PNG ZIP·15초 H.264 전체 디코딩·전체 백업 복원 PASS.
- 3안 적용·설명글 전환·이전 원고 복원·직접 수정 후 재접속·반응형 PASS.
- 루트 `index.html`, `icon.jpg`, `maruni.png`, `ruru.png` 해시 변경 없음.

검수 이미지의 공개 참고 사진은 청인마루의 시공 실적이나 해당 제품의 실제 적용을 뜻하지 않는다. 앱이나 저장소에 포함하지 않았다.
