# 청인마루 시공 아카이브 리뉴얼 · 제품 찾기 개선

검수일: 2026-11-11 (한국). 변경 범위: `marketing/`만. 작업 브랜치: `feature/category-product-finder-20261111`. 기존 실측·마루견적 코드는 수정하지 않았다.

## 1. 전후 비교

| 이전 | 변경 |
|---|---|
| 제품군과 모든 색상 모델이 하나의 긴 목록에 혼재 | 자재 → 카테고리 → 브랜드 → 제품군 → 해당 세부 모델 순서로 탐색 |
| 각 메뉴의 단순 포함 검색, Safari에서 긴 option 숨김에 의존 | 같은 검색 모듈의 실제 결과 버튼과 단계별 네이티브 선택; 원래 선택 ID는 내부에서 유지 |
| 사진 도구·스타일·게시 기능이 전면에 병렬 배치 | 왼쪽 5단계 작업 흐름과 오른쪽 큰 미리보기; 상세 기능은 접어서 보존 |
| 여러 이름의 스타일과 큰 표지 문구 | 하나의 시공 아카이브 시스템, 대표컷/전후비교/디테일의 세 가지 용도 |
| 명조 중심의 큰 카피·사진 위 텍스트 | 실제 Pretendard Regular 자체 호스팅, 사진 아래 짧은 사실 정보 |
| 새로고침마다 준비 완료 알림 | 최초 데이터 준비 때만 안내, 실패/저장/검수 알림 유지 |

동일한 합성 이미지와 두 실제 버전 실행으로 `before-desktop.png`, `after-desktop.png`, `before-mobile.png`, `after-mobile.png`를 기록했다. 참고 사진 화면도 별도로 기록했으며 실제 청인마루 시공으로 주장하지 않는다.

## 2. UI 구조

`01 사진 & 디자인`:

1. **현장 선택** — 기존 현장과 새 현장, 카테고리 기반 제품 찾기.
2. **사진 업로드** — 기존 사진/ZIP 불러오기 재사용.
3. **사진 정리** — 자동 정리 / 수평 맞춤 / 주변 정리 / 원본 비교의 네 버튼. 분석·승인·일괄 다운로드는 검수 상세에 보존.
4. **디자인 적용** — A 대표컷형 / B 전후비교형 / C 디테일형. 전후 비교는 서로 다른 실제 전·후 사진을 직접 연결하거나 기존 확인된 연결을 사용한다. 같은 사진을 전·후로 복제하지 않는다.
5. **저장** — 피드 1080×1350, 릴스·쇼츠 1080×1920, 블로그 원본 비율. 미리보기 옆 빠른 저장도 제공.

PC에서는 왼쪽 흐름·오른쪽 미리보기, 좁은 화면에서는 큰 미리보기를 먼저 보여준 뒤 작업 흐름을 이어 배치한다. 기존 고급 출력·채널 캡션·원본 편집·AI 설정·사진별 제품 지정은 삭제하지 않고 상세 영역으로 옮겼다.

## 3. 카테고리·검색

01 제작, 02 콘텐츠 구성, 현장 등록의 제품 선택에 같은 계층 UI를 적용했다. 03 제품 도감은 카테고리 → 브랜드 → 제품군 → 세부 모델을 펼치는 구조다. 모델 전체를 기본으로 펼치지 않는다. 직접 등록·CSV·제품 수정도 유지한다.

- 브랜드/제품명/모델/실제 모델별 규격을 여러 단어로 AND 검색한다. 선택 직후에도 다른 자재를 통합 검색할 수 있고, 분류를 직접 지정한 경우에는 그 범위에서 찾는다. 결과에 전체/선택 분류 범위를 표시한다.
- `165×1200`, `165*1200`, `165x1200`, `165 x 1200` 표기를 정규화한다. LX 등의 브랜드 문자는 보존한다.
- 한글 초성 검색을 지원한다.
- 정확히 일치하는 모델과 제품군을 우선 표시한다. 같은 모델명이 여러 브랜드·제품에 있으면 Enter로 임의 선택하지 않고 확인하게 한다.
- 결과를 누르면 기존 제품·모델 ID와 실제 규격을 선택한다. 분류나 검색만 바꾸는 동작은 현재 선택/승인 제품 스냅샷을 변경하지 않는다.
- 단종·출시 전 표기는 기본 탐색에서 제외하되 보기를 켤 수 있다. 기존 프로젝트에서 이미 선택한 항목은 해석·복원 가능하다.
- 분류는 등록된 자재/브랜드/제품명에 명시된 말로 **화면에서만** 구성한다. 실제 원본 `category`, `brand`, `model`, `spec`를 수정하지 않는다. 근거가 없는 자재는 기타 바닥재/기타 벽장재에 남긴다. 제품 성능이나 소재를 추정하지 않는다.
- 가격 없는 실제 제품 피드 1,365개 행을 사용해 검증했다. 원본 가격 시트 JSON을 브라우저에 요청하는 기능은 추가하지 않았다.

## 4. 템플릿 구조

`signatureDesign.archiveVersion = 1`이라는 명시적인 추가 식별자를 사용한다. 기존 v1/v2 렌더러는 그대로 유지하고 이 식별자가 있는 프로젝트만 새 렌더러를 사용한다.

공통: 화이트/아이보리 배경, 차콜 글자, 작은 브랜드 표기, Pretendard, 동일한 정보 위계와 여백, 색상 필터/생성형 변경 없는 이미지 배치. 글은 실제 선택한 제품명·모델·규격과 확인한 짧은 설명만 사용한다. 로고를 사진 중앙에 크게 올리지 않는다.

- **A 대표컷형** — 한 장의 실제 공간 사진과 작은 제품 정보.
- **B 전후비교형** — 실제 연결된 전/후 사진을 같은 규칙으로 나란히 배치.
- **C 디테일형** — 실제 디테일 사진과 등록한 짧은 마감 설명.

어느 템플릿도 사진을 자동 크롭하지 않는다. 원본 비율을 유지하므로 가로 사진을 세로 피드에 넣거나 전후 사진을 병렬 배치하면 여백이 생길 수 있다. 사진을 늘리거나 구조를 변형해 화면을 채우지 않는다. 블로그용은 캔버스 자체도 원본 비율이며, 사실 정보는 별도 채널 원고로 제공한다. 블로그 출력의 최대 폭은 기존 규칙대로 1600px이다.

기존 강제 정보 카드/중복 표지를 새 작업에서 생성하지 않는다. 기존 사진 역할은 세 가지 용도로 정리하되, 이전 프로젝트의 고정 시퀀스는 유지한다.

## 5. 사진 보정 범위

기본은 기존의 전체 색상 보호다. 자동 정리와 수평 맞춤은 로컬 분석/검수로 연결되며 사진을 무조건 덮어쓰지 않는다. 수평 맞춤은 검수 계획에서 원근/색상 처리를 제외한다. 승인한 결과만 사용자가 디자인에 연결한다. 원본 비교는 미리보기에만 적용되고 저장 이미지에 섞이지 않는다.

**이번 리뉴얼로 바닥 의미 인식·렌즈 프로필 교정·AI 물체 제거가 완성된 것은 아니다.** 주변 정리는 기존 선택 영역 도구로 안내하며, 연결되지 않은 AI 기능은 연결/동의 필요 상태를 표시한다. 수치·노출을 과장 보정하지 않는다. 상세 한도는 `AUTO-PHOTO-REVIEW-20261111.md`를 따른다.

## 6. 데이터 보호

- IndexedDB DB명·버전·object store를 변경하지 않았다.
- 원본 사진·수동 보정·제품 ID·기존 게시물·승인 내용·고객/성과 기록은 초기화하지 않았다.
- 새로운 기본 디자인은 기존 기본값을 이력에 보관한다. 자동 변경 시 이전 이력을 잘라내지 않는다.
- 사진이 있는 기존 프로젝트는 새 템플릿으로 자동 전환하지 않는다. **아카이브 디자인 적용**을 확인해야 한다.
- 명시적 전환 전에 해당 디자인·시퀀스·문구 구성을 보관하고 **이전 디자인 복원**을 제공한다.
- 기존 전체 백업 및 제작 패키지에 아카이브 식별자가 포함되고, 가져오기/복원 때 유지된다.
- 원래 제품 선택 요소는 호환용으로 내부에 남긴다. 화면에는 새 분류 UI만 보여준다.

## 9. 변경 파일·복구

`product-finder-core.js`, `product-finder.js`, `product-finder.css`, `archive-render.js`, `archive-studio.js`, `archive-studio.css`를 추가했다. Pretendard Regular와 OFL 라이선스를 `fonts/`에 포함했다. `index.html`, `signature-core.js`, `signature-studio.js`, `authoring.js`를 연결/호환 및 반복 알림 축소 목적에 한해 변경했다. 관련 검증 파일과 이 보고서를 추가했다.

기준 커밋 `3e3c6cb`에 이전 배포가 보존되어 있다. 문제 시 이번 변경 커밋만 revert하고, 실측이나 견적 파일을 덮어쓰지 않는다. 앱의 이전 디자인 복원과 전체 JSON 복원도 유지한다. 코드 롤백은 브라우저 저장 원본을 삭제하지 않는다.
